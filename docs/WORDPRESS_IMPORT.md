# WordPress XML import (experimental)

Choose **Import WordPress XML** on the dashboard or in the editor, select a WordPress WXR XML export, review the report, and choose **Create imported project**. This creates a separate local project; it does not modify the source file or publish anything. The initial importer accepts UTF-8 XML exports up to 1 MiB and at most 500 items. XML document type and entity declarations are rejected.

The report identifies skipped item types, images needing separate import, scripts or styles that were not converted, and recognized link-conversion problems. It retains the total issue count and up to 100 details in the project; review the original XML for additional items and unsupported structures.

Posts and pages become editable content blocks with new local paths. Recognized headings and links are converted; links to uniquely identified imported pages are rewritten to their new paths. Other formatting, unmatched or ambiguous links, link fragments, images, attachments, shortcodes, plugins, themes, and server functionality require manual review or separate import. All posts start as drafts. Unpublished pages, including pages with no recognized published status, also start as drafts using the article draft controls; review them before marking them ready. WordPress categories and tags become article tags. A new empty Home page is added. Other item types are counted but not converted. Keep the original export and verify the imported text and paths before using the project.

Marking an imported draft page ready also makes it an article in the generated article index. Review whether that is appropriate for the site before doing so.

The original XML and conversion report are stored as inactive data in the project so unsupported content is not discarded. They can include private WordPress information, such as author details, and are included when the project is saved or shared. To read or copy them, open the editor's JSON/code panel and choose **Inspect imported source**. Source HTML and scripts are not executed by the importer or the read-only source view. This is an initial conversion, not a complete WordPress site reconstruction.

An isolated Windows WebView2 test imported a fictional WXR with an unpublished page, a post, an attachment, a heading, local and unmatched links, an image and a script. It checked the detailed report, separate project, draft statuses, converted heading and link, inactive script, and original XML and report after saving, reopening and viewing them. Clean-Windows acceptance and broader WordPress compatibility remain unverified.
