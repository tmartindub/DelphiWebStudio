# M8 validation record

Last changed: 2026-11-01

On 2026-11-01 the current Vitest run passed 273 tests across 19 files. Two integration tests were skipped by default: the offline browser test and the SFTP backup-fixture comparison. A separate run of the offline browser test passed with an isolated browser profile and network name resolution disabled after the dependency update. The SFTP fixture comparison was not run in this validation; no website was published. TypeScript and the production editor build passed. The standard `npm run lint` also passed after generated output and test folders were excluded from ESLint's scan.

The local preview `bin/DelphiWebStudio-Preview-M8-20261101-2100` combines the previously tested desktop shell with the editor build as it stood when that preview was staged; it predates the subsequent HTML source-block and dependency updates. Its staged editor files were compared with its build; an isolated startup check kept the application running for eight seconds, and the dashboard rendered. The complete installed desktop workflow has not been checked in this preview. A separate isolated current-build desktop test selected a synthetic folder through the actual Windows folder picker, reviewed the report, created the two-page project, and saved it using the modern save dialog. The saved project retained the original source and read-only source block; all three selected fixture files matched their originals afterward. The fixture did not include image files. Another isolated desktop check using the updated build passed the code panel's keyboard shortcut, accessible error, stale-draft protection, and close-focus checks; this is not a full accessibility audit.

An isolated offline browser checked an exported five-page sample at widths of 375, 768 and 1440 pixels: the home page had no horizontal document overflow and its About link opened the local About page at each width. Axe-core 4.14.0 reported no violations or incomplete checks for its WCAG 2 A/AA and 2.1 A/AA rules on the home page at all three widths, or on the other four pages at 375 pixels. This is a limited automated sample check, not a full accessibility audit or proof for other sites and content.

An isolated desktop test compiled against the current shell deliberately terminated its own test process during an in-progress revision write. On restart with the same test profile, the earlier five-page revision was available and its original PDF bytes matched. This verifies that interruption scenario; it does not prove recovery from power loss, device failure, or every possible interruption.

The static importer retains original HTML and CSS as inactive project data. Pages with detected unconverted tags also contain a read-only source block with the original body as inert text; that block is excluded from website export. This preserves the source for review without executing imported markup, but it does not reconstruct unsupported content in the website. Import conversion, broader compatibility, and the corresponding security review remain incomplete.

A separate isolated current-build desktop test selected a fictional WordPress XML export through the actual Windows file dialog, reviewed its conversion report, created the imported project, and viewed the converted page and links. Saving, reopening and retained-source checks were covered by the earlier synthetic-input desktop test. Broader WordPress compatibility remains unverified.

On 2026-11-01 `npm audit` initially reported 44 vulnerable dependency entries, including two critical development-tool findings. A non-forced compatible dependency update, with lifecycle scripts disabled, reduced the full report to 22 findings (18 moderate and four high), all in development dependencies according to `npm audit --omit=dev`, which reported zero. The remaining full-audit findings include transitive development tooling for Vercel and linting; npm proposed breaking dependency changes, which were not applied. Review their applicability and remediation before release. Audit results do not by themselves establish exploitability or complete security. A clean `npm ci --ignore-scripts` succeeded; after it, 273 tests passed (two skipped), the production editor built, and an isolated desktop test saved, reopened and exported a five-page project with its original PDF. Source and test lint also passed after the update.

The four high-severity entries in that full audit are `@vercel/node` and its `path-to-regexp`, `undici`, and `@fastify/busboy` dependency paths. The project's three optional server API files import `@vercel/node` types only; a separate TypeScript check passed, and the desktop editor's source does not import that package. The installed `@vercel/node` package pins `path-to-regexp` 6.1.0 and `undici` 5.28.4, so forcing transitive major-version replacements could affect the optional Vercel build/runtime. No Vercel deployment was performed; assess and test that path before using or releasing it. This scope assessment does not remove the remaining development-tool risks.
